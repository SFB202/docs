    네이밍 컨벤션¶

    0) 공통 규칙¶

    • 클래스/레코드/인터페이스: PascalCase

    • 메서드/변수: camelCase

    • 상수: UPPER_SNAKE_CASE

    • 패키지/폴더: lowercase

    • 약어 규칙: 2~3글자 약어는 대문자 유지(API, DTO, JWT), 그 외는 단어로 풀기 권장

    • 한글은 문서/주석/커밋에서만 사용, 코드 식별자는 영문 권장(일관성)

    1) API 레이어 (api/*)¶

    1.1 Controller¶

    • 형식: {Domain}Controller

    • 예: AuthController, RoomController, UserController, InviteController

    1.2 Request DTO (api.request)¶

    • 형식(권장): {Action}{Domain}Request

    • 예:

      • LoginRequest

      • CreateRoomRequest

      • UpdateUserProfileRequest

      • GenerateInviteRequest

      • JoinRoomRequest

    1.3 Response DTO (api.response)¶

    • 형식(권장): {Action}{Domain}Response 또는 {Domain}{View}Response

    • 예:

      • LoginResponse

      • RoomSummaryResponse

      • RoomDetailResponse

      • ParticipantsResponse

      • InviteCodeResponse

    1.4 Config / Security¶

    • Config 형식: {Purpose}Config

      • 예: WebConfig, CorsConfig, JacksonConfig

    • Security 형식:

      • 설정: SecurityConfig

      • 필터: {Purpose}Filter (예: JwtAuthenticationFilter)

      • 인증 사용자: UserPrincipal 또는 AuthUser

    2) Service 레이어 (service/*)¶

    2.1 Service 인터페이스 (service.service)¶

    • 형식: {Domain}Service

    • 예: AuthService, RoomService, UserService, InviteService

    2.2 Service 구현 (service.service.impl)¶

    • 형식: {Domain}ServiceImpl

    • 예: AuthServiceImpl, RoomServiceImpl

    2.3 Command (service.command)¶

    • 형식: {Verb}{Domain}Command

    • 규칙: “상태 변경(생성/수정/삭제)”만 Command로 표현

    • 예:

      • CreateUserCommand

      • LoginUserCommand

      • UpdateUserProfileCommand

      • CreateRoomCommand

      • GenerateInviteCommand

      • JoinRoomCommand

    2.4 Query (service.query)¶

    • 형식: {Verb}{Domain}Query

    • 규칙: “조회/검색/필터/페이징”만 Query로 표현

    • 예:

      • GetMyRoomsQuery

      • GetRoomParticipantsQuery

      • FindUserByLoginIdQuery

      • SearchRoomsQuery

    3) Data 레이어 (data/*)¶

    3.1 Entity (data.entity)¶

    • 형식: {Domain}Entity

    • 예: UserEntity, RoomEntity, InviteEntity, RoomParticipantEntity

    3.2 Repository (data.repository)¶

    • 형식(권장): {Domain}Repository

    • 기술이 필요하면 접미어로 명시:

      • JPA: {Domain}Repository (interface extends JpaRepository…)

      • MyBatis: {Domain}Mapper

    • 예:

      • UserRepository

      • RoomRepository

      • InviteRepository

      • UserMapper

    3.3 External (data.external)¶

    • 형식: {Vendor}{Purpose}Client 또는 {Vendor}{Api}Client

    • 예:

      • GithubOAuthClient

      • NaverMapClient

      • PublicDataClient

    3.4 Util (data.util)¶

    • 형식: {Purpose}Util / {Purpose}Mapper

    • 예:

      • EntityMapper

      • ExternalRequestUtil

    4) 메서드 네이밍 규칙(서비스 기준)¶

    • 동사 + 목적어(도메인) 형태를 유지

    • Result 기반이므로 “try” 같은 모호한 접두사 지양

    예:

    • login(...)

    • logout(...)

    • createRoom(...)

    • getMyRooms(...)

    • getParticipants(...)

    • generateInvite(...)

    • joinRoom(...)

    5) DTO/Command/Query 필드 네이밍¶

    • Request/Command/Query: 입력 필드는 사용자 관점

      • 예: loginId, password, roomId, inviteCode

    • Entity: DB 컬럼과 1:1이면 동일 의미 유지

      • 예: createdAt, deletedAt, ownerId

    6) 테스트 네이밍 (JUnit)¶

    • 클래스: {TargetClass}Test

      • 예: UserServiceImplTest

    • 메서드: method_condition_expected

      • 예: login_success_returnsUserId()

      • 예: createRoom_duplicateName_returnsConflictError()
