## 1) 인증 / 로그인

### 목적

- 사용자는 GitHub 계정 연동(OAuth)으로 로그인한다.
    

### 기능 요구사항

|기능|상세|
|---|---|
|로그인|GitHub OAuth 연동 로그인|
|세션 유지|로그인 상태 유지(토큰/세션 기반)|
|로그아웃|세션 종료 및 클라이언트 상태 초기화|

---

## 2) 유저 관리

### 목적

- 로그인한 유저의 기본 정보와 방/회의/이슈 등 서비스 내 활동을 식별한다.
    

### 기능 요구사항(초안)

|기능|상세|
|---|---|
|유저 프로필 조회|GitHub 프로필(이름/아이디/아바타 등) 기반|
|권한/역할|방 단위로 역할(관리자/멤버 등) 구분|
|활동 기록|최근 참여 회의/생성 이슈 등 연동 가능한 범위로 기록|

---

## 3) 마이페이지 (로그인 직후 기본 화면)

### 목적

- 사용자의 최근 활동(회의)을 빠르게 확인한다.
    

### MUST (기능 요구사항)

- 최근 참여한 회의 5~10개 노출
    
- 회의 리스트 아이템에 아래 정보 표시
    
    - 회의 제목
        
    - 참가자(요약 형태 가능: “3명”, “A,B 외 2명”)
        
    - 날짜(및 시간)
        

### SHOULD (권장)

- “다가오는 회의(예약)” 영역 제공: 사용자의 예정된 회의 5~10개 노출
    
- 예정 회의 아이템에 아래 정보 표시
    
    - 회의 제목
        
    - 날짜·시간
        
    - 방 이름(또는 방 썸네일)
        
    - 참가자 수
        

### 데이터 표시 항목

|항목|설명|
|---|---|
|제목|회의 이름|
|참가자|참여자 리스트/요약|
|날짜|회의 진행 일시|

---

## 4) 방 리스트 (사이드바)

### 목적

- 사용자가 참여 중인 방을 빠르게 이동/확인한다.
    

### 기능 요구사항

- 로그인 성공 시, 내가 참가한 방 목록 표시
    
- 방 리스트 아이템 표시
    
    - 방 대표 이미지(썸네일)
        
    - 방 이름
        
    - 알림 표시(새 이벤트/미확인 메시지/새 회의록/새 이슈 등)
        

---

## 5) 방 (Room)

### 목적

- 협업 단위 공간. 레포지토리/회의/이슈/회의록이 방 단위로 묶인다.
    

### MUST (기능 요구사항)

- 관리자는 방 생성 가능(방 이름 입력)
    
- 로그인 후 사용자는 방 목록 확인
    
- 사용자는 새 방 생성 가능(권한 정책에 따라 “관리자만”으로 제한 가능)
    
- 방 입장 시 프로젝트(레포지토리)를 생성하거나 불러오기 가능
    
- 라운지에서 GitHub ID 검색으로 친구 추가 / Collaborator 자동 초대 연동
    
- 방 내부 사이드바에 “진행 중 회의 / 완료된 회의” 리스트 표시
    

### MUST (회의 예약/캘린더)

- **관리자**는 회의를 **예약 추가/수정/취소**할 수 있어야 한다.
    
- 캘린더에 표시되는 날짜들에 **등록된 회의(예약/완료)가 표시**되어야 한다.
    
- 방 사이드바의 회의 리스트는 최소 아래 상태를 구분 표시할 수 있어야 한다.
    
    - 예정(예약됨) / 진행 중 / 완료 / 취소
        

### MUST (초대 링크)

- **관리자**는 초대 링크를 **생성/삭제**할 수 있어야 한다.
    
- **관리자**는 초대 링크의 **유효기간 설정/수정**을 할 수 있어야 한다.
    
- 사용자는 초대 링크로 접속해 **방에 접속**할 수 있어야 한다.
    
- 초대 링크 랜딩 페이지에서 사용자는 아래 정보를 확인할 수 있어야 한다.
    
    - 방 제목 / 참가자 수 / GitHub 레포
        

### 세부 요구사항(정리)

|기능|상세|
|---|---|
|레포지토리 연동|프로젝트 이름 기반으로 새 GitHub 레포 생성 또는 기존 레포 불러오기|
|멤버 초대 연동|GitHub ID 검색 → Collaborator 초대 자동화|
|회의 목록 표시|방 단위로 진행/완료 회의 구분 표시|
|회의 예약(캘린더)|예약 CRUD(관리자) + 캘린더 날짜에 회의 표시|
|초대 링크|링크 생성/삭제/유효기간(관리자) + 링크 접속 시 방 정보 확인/입장|

## 6) 라운지 (Room Dashboard)

### 목적

- 방 단위 활동 요약 + 최근 회의 + 진행 중 이슈를 한 화면에서 보여준다.
    

### MUST (기존 구성)

- 이번 주 활동 요약(주간 통계)
    
    - 이번 주 생성 이슈 수 / 완료 이슈 수 / 회의 시간(총합)
        
- 최근 회의 카드(가장 최근 1개)
    
    - 날짜 / 이름 / 진행시간 / 참여자 / 생성 이슈 수 / 링크(또는 이동)
        
- 진행 중 이슈 리스트(우선순위 기반)
    
    - 번호 / 제목 / 생성 유저 / 생성 일시
        

### SHOULD (권장: 예약 위젯)

- “다가오는 회의(예약)” 위젯/영역 제공
    
    - 다음 예약 1개(또는 n개) 표시: 제목 / 시간 / 참가자 수 / 입장 버튼
        
    - 관리자는 여기서도 예약 **추가/수정/취소**로 진입 가능

## 7) 텍스트 채팅

### 목적

- 방/회의실에서 커뮤니케이션을 지원한다.
    

### 기능 요구사항

- 입장 시 최신 채팅 10~20개 로드
    
- 과거 채팅 시간순 조회(무한 스크롤/페이지네이션 등)
    
- 메시지 표시: 프로필 / 이름 / 시간 / 내용
    
- 수정/삭제(권한 정책 필요)
    

---

## 8) 회의실 (Real-time Meeting)

### 목적

- OpenVidu 기반 실시간 음성 회의 + 화면 공유 + 채팅 제공
    

### MUST (기능 요구사항)

- OpenVidu로 실시간 음성 대화
    
- 화면 공유(전체 화면/특정 앱/브라우저 탭)
    
- 텍스트 채팅 제공
    
- 방마다 고유 세션 ID 부여로 보안 강화
    

### SHOULD (권장: 예약 연계)

- 예약된 회의(예정)에서 “회의 시작/입장”을 통해 회의실로 자연스럽게 연결되어야 한다.
    

---

## 9) 이슈 (GitHub 연동)

### 목적

- 이슈를 서비스에서 관리하되, 실제 저장/원장은 GitHub 레포지토리로 반영한다.
    

### 기능 요구사항

- 이슈 목록 시간순 조회 / 검색
    
- 관리자는 작성 템플릿 생성/수정/삭제 가능
    
- 템플릿 기반 폼으로 이슈 생성 → GitHub API 호출 → 레포에 이슈 생성
    
- 생성 결과는 라운지에 실시간 반영
    

---

## 10) 회의 요약 (Speech-to-Text + AI Summary)

### 목적

- 회의 중 음성을 자동 기록하고, 종료 시 요약/회의록을 생성하여 공유한다.
    

### 기능 요구사항

- 회의록 검색 가능
    
- 회의실 입장 시 음성 인식/기록 자동 시작
    
- 종료 버튼 클릭 시
    
    - 스크립트 전송 → AI 요약 생성 → 마크다운/에디터 형태로 수정 가능 저장
        
- 생성된 회의록은 방 라운지에 즉시 게시

## 권한(역할) 기준 요약

|구분|가능한 작업|
|---|---|
